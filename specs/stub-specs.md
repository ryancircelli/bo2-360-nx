# Specs for imported system functions with no reference implementation

Stream stub-noref-research, 2026-11-26. Docs only, no code.
Scope: 191 functions that one or more of our 11 games import (bo2 bo1 fh1 nfshp nfsmw nfsmw2012 gears ac1 halo3 me2 fallout3), that are stubs in our SDK, and that our pinned references (xenia-canary at our sync point, rexglue v0.11) also leave as stubs.
Full list with current macros: /tmp/bo2/stub-noref-research/noref_imported.tsv.

## How to read this
- **Origin** (the owner's sources rule, 11-26 22:03):
  - `upstream` = port from xenia-canary HEAD 2da2519 (2026-11-24). Canary is a credited upstream, so the code can be copied.
  - `documented` = behaviour from public Microsoft documentation of the matching Windows/NT/Winsock/WinHTTP function.
  - `call-site` = behaviour read from our own generated game code (the instructions after the call).
  - `clean-room` = write from this spec alone, with no outside source open.
  - `left` = keep the stub, for the reason given.
- **xenia-edge** (has207/xenia-edge, a Xenia fork, BSD-3 under the same "Ben Vanik" notice) implements about 30 of these functions: the whole XHttp set, the XNet key, QoS and connect functions, NtCancelIoFile, getpeername, WSAEventSelect, XamGetToken/FreeToken and XamGetSystemVersion. It is not on the credited list, so it is **ideas only** until the manager rules. Porting it would add no new licence text, because the notice is the same as Xenia's. Decision requested in the hand-over.
- Return values: `0x32` = ERROR_NOT_SUPPORTED. In BO2, an HRESULT caller does `cmpwi r3,0; blt fail`, so **0x32 reads as success** and the caller then reads an output that was never written. Any function a caller checks as an HRESULT must return a negative HRESULT, never 0x32.
- A plain `REX_EXPORT_STUB` leaves r3 as whatever the caller passed (usually a pointer, so it looks like a positive number). A caller that tests the result takes the success path on junk.
- Confidence: H = upstream or documented, M = call site plus a reasoned value, L = guess; L entries stay stubs, with a deliberate return value and a comment.
